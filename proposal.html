When Would We Pay?

Firebase Spark (free) handles up to 100 simultaneous device connections per database. For a 100-player event, typically 20–30 devices are connected at once (scorers + spectators viewing brackets) — well within limits. If we ever needed to scale beyond that, Firebase Blaze starts at ~$25/month. GitHub Pages has a 100 GB/month bandwidth limit — equivalent to serving the tournament page to ~100,000 visitors monthly.

Firebase Realtime Database — Detailed Analysis

PROS

  • ✓
    Real-time sync — all devices see score updates within milliseconds, no refresh needed
  • ✓
    Already integrated — existing IAG tournaments use it; zero new setup cost
  • ✓
    Generous free tier — 1 GB storage + 10 GB/month download = thousands of tournaments
  • ✓
    No server — client-side JS SDK only; no backend to maintain or pay for
  • ✓
    Offline support — scores cached locally if connection drops; syncs when back online

CONS / RISKS

  • ✗
    100 connection cap — Spark free plan allows 100 simultaneous clients; rare issue at typical event sizes
  • ✗
    Shutdown on overage — if limit hit, service pauses until next billing cycle (fixable: upgrade to Blaze)
  • ✗
    API key exposure — Firebase config is visible in HTML source; mitigated by Firebase Security Rules
  • ✗
    Google dependency — Google could change pricing or terms (mitigated: data also backed up to GitHub)

Mitigation Strategy

All tournament data (schedule, results, metadata) is also saved to the GitHub repository as JSON files — giving a complete, vendor-independent backup of every event. Live scoring uses Firebase; permanent record uses GitHub.
